# SPEC.md. Личная игра для английского (рабочее название Nemesis)

Этот файл читает Claude Code. Задача: создать проект с нуля по этой спецификации, идти по этапам из раздела 17, после каждого этапа выполнять самопроверку из раздела 16, пушить в репозиторий по правилам раздела 19, потом останавливаться и показывать результат.

Первым делом создай короткий `CLAUDE.md` (стек, команды, правила кода, правило самопроверки, правила git, ссылка на этот файл), чтобы не держать всю спецификацию в контексте постоянно.

## 1. Что это и для кого

Личное приложение одного пользователя. Публикации в сторах нет, регистрации нет, бэкенда нет.

Пользователь
- Разработчик (React, TypeScript), живёт в Баку, интерфейс нужен на русском.
- Английский B2. Понимает хорошо. Слабое место это быстрое говорение и письмо. Фразу приходится каждый раз собирать с нуля.
- Цель: свободный разговорный английский на все случаи жизни. Не экзамен и не только работа.
- Учит через живую задачу. Абстрактные уроки и длинные объяснения грамматики не работают.
- Занимается в основном с телефона Xiaomi 11 Lite (Android среднего класса, Chrome, экран примерно 393×873 CSS px). Компьютер вторичен.
- Бюджет на ИИ нулевой. Только бесплатные варианты.

Следствия для продукта
1. Единица обучения это фраза в контексте (chunk), а не отдельное слово. Слово учится внутри фразы.
2. Почти все действия требуют произвести ответ (напечатать, собрать, сказать). Выбор из вариантов допустим только на первой ступени.
3. Контент про его реальную жизнь, а не про "London is the capital".
4. Объяснения на русском, одно или два предложения. Английский текст простой, без тяжёлых конструкций.
5. Управление одной рукой.

## 2. Главная идея

Это одна цельная игра, а не набор упражнений. Жанр roguelike. Сессия это **поход** по карте из узлов. Враги это фразы. Ответ на английском это удар. Фраза, на которой ошибся, не умирает, а уходит и возвращается сильнее. Так главное требование (не отпускать, пока не выучишь) становится сюжетом игры.

Три закона, которые нельзя нарушать
1. **Каждое действие в бою это ответ на английском.** Никаких механик, где можно победить, не отвечая.
2. **Игровые эффекты никогда не меняют учебную оценку.** Усиления, криты и здоровье влияют на награды и ход похода, но оценка для FSRS всегда честная.
3. **Проигранный поход не отнимает выученное.** Прогресс по фразам сохраняется всегда.

## 3. Платформа и стек

Веб-приложение PWA, mobile-first. Устанавливается на домашний экран, работает офлайн.

- Vite + React + TypeScript (strict)
- Zustand для состояния
- Dexie (IndexedDB) для всех данных
- ts-fsrs для интервальных повторений
- motion (framer-motion) для анимаций, canvas-confetti для празднований
- Tailwind CSS
- vite-plugin-pwa (офлайн, установка)
- Web Speech API. speechSynthesis для озвучки, SpeechRecognition для говорения
- Vitest для тестов движка, Playwright для самопроверки и e2e
- Деплой на бесплатный статический хостинг с HTTPS (Vercel или GitHub Pages). HTTPS обязателен для микрофона и установки PWA

Не использовать: three.js, тяжёлые модели в браузере (transformers.js, WebLLM), любые платные API, UI-киты с большим бандлом.

Первый экран до 250 КБ gzip, экраны боя и сцены подгружаются лениво.

## 4. Учебный движок (под игрой)

Чистый модуль `src/engine/` без React. Принимает состояние и время, возвращает следующий шаг. Время передаётся параметром (инъекция часов), чтобы можно было тестировать "следующий день".

### 4.1 Типы элементов

1. **phrase**. Готовая фраза или устойчивое сочетание ("it depends on", "I ended up doing", "to be honest"). Основной тип.
2. **word**. Слово, всегда с фразой-носителем и минимум двумя контекстами.
3. **pattern**. Грамматическое правило, на котором пользователь стабильно ошибается. Это набор упражнений, а не карточка.

Стартовые pattern (известные повторяющиеся ошибки пользователя)
- `articles`. Пропуск и путаница a / the / без артикля
- `habit-present-simple`. "can" вместо Present Simple для привычек ("I can drink coffee in the morning" вместо "I drink coffee")
- `adverb-order`. Место just, already, always, usually в предложении
- `sv-agreement`. Согласование подлежащего и сказуемого (he work → he works)
- `calques`. Кальки с русского и азербайджанского ("master" вместо mechanic, "feeds" вместо "my feed")

### 4.2 Ступени и приёмы

У каждого элемента одна карточка FSRS и ступень. Ступень определяет минимальный приём, которым врага можно ударить.

| Ступень | Навык | Приёмы |
|---|---|---|
| 0 | новый | Знакомство |
| 1 | узнаю | Свайп, На слух |
| 2 | собираю | Сборка, Пропуск |
| 3 | вспоминаю | Перевод, Диктант |
| 4 | говорю | Голос, Своя фраза |
| 5 | использую | Экспромт, использование во Встрече |

- Верный ответ поднимает ступень на 1. Ошибка опускает на 1 (не ниже 1) и ставит Again.
- На одной ступени приём выбирает движок, но не тот же, что в прошлый раз для этого элемента.
- Элемент выучен, когда пройдена ступень 5 и интервал FSRS не меньше 21 дня. После этого он изредка возвращается только приёмами ступеней 4–5.

Оценка для FSRS
- ошибка → Again
- верно, но с подсказкой, с опечаткой или после заполнения шкалы замаха → Hard
- верно → Good
- верно, до середины шкалы замаха и без подсказки → Easy

### 4.3 Долг

- Ошибся. Элемент становится должником.
- Должник возвращается через 3–5 других ответов и обязательно другим приёмом.
- Долг закрыт после двух верных ответов подряд двумя разными приёмами.
- Незакрытые долги переходят в следующий узел, а после конца похода в следующий поход.

### 4.4 Немезиды

Элемент становится немезидой, если всего 3 провала или провал в двух походах подряд.
- Получает мнемонику и три новых контекста (от ИИ, если доступен, иначе из запасных примеров seed).
- Приходит в каждый поход, пока не побеждена в три разных дня.
- Активных максимум 5, остальные ждут в очереди.

### 4.5 Pattern

Выучен, когда точность не ниже 90% за последние 20 попыток, растянутых минимум на 5 дней. Если ИИ позже находит эту ошибку в свободной речи пользователя, pattern снова становится активным.

### 4.6 Регулятор нагрузки

- Новых элементов в день по умолчанию 6 (настройка 0–12).
- Если долги + повторения на сегодня больше 30, новых 0.
- Приоритет очереди: долги → немезиды → повторения → новые.
- Выбор пути на карте меняет только состав типов узлов. Боевые узлы всегда берут элементы из очереди по приоритету, поэтому увернуться от повторений выбором пути нельзя.

### 4.7 Проверка ответа

- Без учёта регистра и пунктуации, сокращения равны полным формам (I'm = I am), у элемента есть список `accept`.
- Одна опечатка в слове длиннее 4 букв считается верным ответом с оценкой Hard и показом правильного написания.
- Голос: целевая фраза есть в распознанном тексте и совпадение слов с эталоном не ниже 0.8.

## 5. Поход

### 5.1 Цикл

Лагерь → карта → узел → награда и выбор усиления → следующий узел → финальный босс → итог → лагерь.

Обычный поход это 6 узлов плюс босс, примерно 30 ответов, 10–15 минут. Состояние сохраняется после каждого ответа, поход можно закрыть и продолжить.

**Вылазка** это короткий режим на 2 минуты. Один узел Засада (долги и одна немезида). Засчитывается в серию дней.

### 5.2 Карта

Генерируется из seed похода. 6 шагов, на каждом шаге выбор из 2–3 узлов. Игрок видит типы узлов на два шага вперёд.

Типы узлов
- **Засада.** Должники из прошлого похода. Если долги есть, это всегда первый узел без выбора.
- **Стычка.** 4–5 врагов из очереди повторений.
- **Разведка.** Новые фразы. Сначала Знакомство, потом первый лёгкий бой с ними. Меньше риска, меньше рун.
- **Логово.** Немезида. Высокий риск, большая награда. Появляется, только если есть активная немезида.
- **Привал.** Восстановление 2 здоровья и тренировка у костра (5 упражнений Ловушка на активный pattern). Чистая тренировка даёт бесплатное усиление.
- **Встреча.** Сцена-диалог, где ответ меняет исход (раздел 8). Максимум одна за поход.
- **Эхо.** Финальный босс, всегда последний.

Правила генерации: минимум один Привал, Логово не раньше третьего шага, два одинаковых типа подряд на одном пути не ставить.

### 5.3 Бой

Экран: сверху враг (силуэт, имя, шкала замаха), в центре задание, внизу зона ответа и здоровье героя.

- У героя здоровье на весь поход. Старт 5.
- Враг показывает задание. Идёт **шкала замаха** (время зависит от приёма). Ответ до заполнения шкалы это **перехват**, он даёт крит (двойные руны). Ответ после заполнения это обычный удар без штрафа по здоровью.
- Верный ответ это удар по врагу. Неверный это удар врага по герою, минус 1 здоровье. После ошибки показывается правильный вариант, озвучка и одно предложение почему.
- **Рискнуть.** Перед ответом можно выбрать приём выше требуемой ступени. Успех даёт больше урона и рун, а ступень элемента прыгает сразу до уровня этого приёма. Провал это обычная ошибка. Так знакомые фразы проходятся быстро, а выбор приёма становится решением.
- **Комбо.** Серия верных подряд умножает руны (до x3). На комбо 10 восстанавливается 1 здоровье.
- Здоровье 0 это **отступление**. Поход закончен, руны похода делятся пополам, долги остаются. Новый поход можно начать сразу, блокировок нет.

Стартовые числа держать в одном файле `src/game/balance.ts`, их придётся подкручивать после живой игры.

### 5.4 Враги

Внешность врага генерируется процедурно из id элемента (SVG-силуэт, цвет, глаза, детали), без картинок. Один и тот же элемент всегда выглядит одинаково, чтобы его узнавали в лицо.

- **Тень.** Обычный элемент на повторении. Умирает от одного верного удара приёмом своей ступени или выше.
- **Должник.** После ошибки враг уходит в туман, возвращается через 3–5 ответов в другом обличье (другой приём) и требует двух ударов подряд разными приёмами.
- **Немезида.** Элитный враг с именем (сама фраза), счётчиком побед над героем и шрамами. Бой это три разных приёма подряд без права на ошибку. Ошибка означает, что сегодня она победила. Она визуально растёт и вернётся завтра. Победа в три разных дня уничтожает её навсегда, трофей уходит в Зал.
- **Хамелеон.** Враг-pattern. Выглядит как обычное предложение, в котором спрятана типичная ошибка пользователя (или её нет). Приём Ловушка.
- **Эхо.** Финальный босс. Собирается из всех элементов, на которых была ошибка в этом походе. Каждая фаза это один из них самым сложным доступным приёмом. Если ошибок не было, это "чистый поход" с бонусом, а Эхо собирается из трёх самых трудных по FSRS элементов дня.

## 6. Приёмы (форматы ответа)

Общее
- Зона ответа в нижней половине экрана, цели касания не меньше 48px.
- Озвучка английского через speechSynthesis (en-US или en-GB, выбор в настройках).
- В полях ввода отключить автозамену (`autocorrect="off" autocapitalize="off" spellcheck="false"`), иначе клавиатура подсказывает ответ.
- Экранная клавиатура не должна перекрывать задание и кнопку ответа (visualViewport).

**Знакомство** (ступень 0, только в Разведке). Фраза, перевод, пример из жизни, озвучка. Кнопки "Повторил вслух" и "Знаю". "Знаю" сразу запускает Рискнуть приёмом Перевод.

**Свайп** (1). Английская фраза в предложении и русский смысл. Вправо, если совпадает, влево, если нет.

**На слух** (1). Звучит предложение без текста. Выбрать из трёх смысл сказанного.

**Сборка** (2). Русское предложение, внизу плитки с английскими словами и 2–3 лишние. Лишние подбираются под ошибки пользователя (лишний артикль, неверное место just, форма без -s).

**Пропуск** (2). Предложение с пропуском на месте целевой фразы. Напечатать. Подсказка показывает первые буквы слов.

**Перевод** (3). Русская фраза или ситуация ("Скажи, что это зависит от погоды"). Напечатать по-английски с нуля.

**Диктант** (3). Звучит предложение с целевой фразой. Напечатать целиком. Переслушать можно один раз.

**Голос** (4). Русская ситуация, сказать по-английски в микрофон. Самый сильный удар в игре. Если распознавание недоступно, показывается эталон и самооценка (Сказал верно / С ошибкой / Не смог).

**Своя фраза** (4). Вопрос про жизнь пользователя, в ответе нужна целевая фраза ("Use *end up* to tell how your last weekend went"). С ИИ проверка по контракту из раздела 10. Без ИИ проверка наличия фразы, три образца и самооценка.

**Экспромт** (5). Новая ситуация на русском, которую пользователь ещё не видел, 6 секунд на начало ответа, голос или печать. Использование целевой фразы во Встрече тоже считается ударом ступени 5.

**Ловушка** (pattern). Тапнуть на неверное место в предложении и исправить. Если ошибки нет, нажать "Всё правильно".

## 7. Усиления и развитие

### 7.1 Усиления на один поход

После каждого узла выбор одного из трёх. Усиления подталкивают к более трудным приёмам и никогда не пропускают ответы.

Стартовый набор
- **Голос вождя.** Удары Голосом дают двойные руны, крит Голосом лечит 1 здоровье.
- **Азарт.** Рискнуть даёт +50% рун.
- **Память рода.** Первая ошибка в походе не отнимает здоровье.
- **Щит переписчика.** Первая опечатка в каждом бою не снижает награду.
- **Холодная голова.** Шкала замаха заполняется на 30% медленнее.
- **Охотник.** Победа над немезидой даёт +2 здоровья.
- **Тёплый костёр.** Привал лечит 3 вместо 2.
- **Следопыт.** На карте видно на один шаг дальше.
- **Чистый клинок.** Каждый бой без ошибок даёт сундук.
- **Эхо-ловец.** Каждая фаза Эхо даёт тройные руны.
- **Упрямство.** Закрытый долг лечит 1 здоровье.
- **Второе дыхание.** Один раз за поход при здоровье 0 подняться с 1.

### 7.2 Развитие между походами

- **Руны.** Валюта. Тратится в Лагере.
- **Лагерь.** Постоянные улучшения: максимум здоровья (до 8), четвёртый вариант при выборе усиления, стартовое усиление, заморозки серии, облик героя и темы.
- **Уровень героя.** Растёт от опыта. Опыт за трудные приёмы выше.
- **Земли.** Колоды это области мира по сферам жизни. Новая земля открывается, когда освоена часть предыдущей. У каждой свой фон и свой набор сцен.
- **Летопись.** Все элементы как существа со статусом: не встречал, встречал, ранен (ступень), приручён (выучен). Процент по каждой земле.
- **Зал трофеев.** Побеждённые немезиды с датой и числом их побед над героем.
- **Серия дней** с заморозками. Пропуск при наличии заморозки серию не ломает. Никаких упрёков за пропуск.

### 7.3 Празднования

- удар: враг вздрагивает, цифра рун вылетает, короткий звук
- крит: замедление на 150 мс и вспышка
- должник закрыт: враг рассыпается, вибрация
- ступень поднята: значок перелетает на карточку врага
- победа над немезидой, над Эхо, новый уровень, новая земля: полноэкранная сцена с конфетти и вибрацией
- экран итога: что выучено, какие долги закрыты, кто стал немезидой, кто побеждён, сколько рун

Звуки синтезировать через Web Audio API (без файлов). Вибрация через `navigator.vibrate`. Обе вещи отключаются в настройках.

## 8. Встречи (сцены)

Узел, где язык решает исход. Жизненная ситуация, персонаж и цель (уговорить, договориться, выкрутиться, расположить к себе). 3–4 обмена репликами, голосом или текстом, 25 секунд на ответ.

- Сверху чипы с 2–3 фразами из сегодняшних. Использовал фразу, чип гаснет, это удар ступени 5 по этой фразе.
- ИИ решает исход: успех, частичный успех, провал. От исхода зависит награда.
- Исправления показываются после сцены, чтобы не ломать погружение. Формат привычный пользователю: ❌ как сказал, ✅ как надо, одно предложение с правилом.
- **Ошибки материализуются.** Каждая ошибка из сцены превращается во врага в следующем боевом узле. Она либо привязана к существующему pattern (приходит Хамелеон), либо становится новым элементом phrase с правильным вариантом.
- Без ИИ сцена идёт по сценарию из seed с образцовыми ответами и самооценкой.

Сцены для старта: договориться с арендодателем о цене, объяснить на паспортном контроле цель поездки, small talk с незнакомцем в баре, уговорить друга посмотреть твой любимый сериал, рассказать о своём проекте человеку не из IT, вернуть заказ в кафе, поспорить о простом философском вопросе, рабочий созвон с плохими новостями, лёгкое собеседование.

## 9. Контент

### 9.1 Seed (генерирует Claude Code, лежит в `src/content/seed/*.json`)

Не меньше 300 элементов phrase и word уровня B2–C1. Земли
- Знакомства и small talk
- Мнение, согласие, спор, сомнение
- Быт и повседневность
- Эмоции и состояния
- Истории, планы, пересказ
- Работа и разработка (созвоны, объяснить задачу, код-ревью)
- Дорога и переезд
- Фразовые глаголы в живых контекстах
- Связки и заполнители пауз (well, to be honest, the thing is, what I mean is)

Для каждого элемента: `en`, `ru`, `accept[]`, минимум 3 предложения-контекста с переводом, 2 разные ситуации на русском (для Перевода и Экспромта), 1 вопрос для Своей фразы, 2 ложных смысла для Свайпа.

Темы примеров из мира пользователя: разработка и свои проекты, кафе с друзьями, спортзал, исторические сериалы и аниме, игры, философия и книги, Баку, планы на переезд. Никаких школьных примеров.

Для каждого pattern: объяснение на русском в два предложения и минимум 40 упражнений Ловушка.

Для Встреч: 9 сценариев с репликами персонажа и образцовыми ответами.

### 9.2 "Из жизни" (главный источник нового контента)

Экран в Лагере с тремя входами
1. **Не смог сказать.** Пользователь пишет по-русски, что хотел сказать. ИИ даёт естественный английский вариант, выделяет фразу для запоминания, создаёт элемент.
2. **Вставить текст.** Любой английский текст (статья, субтитры, переписка, вакансия). ИИ вытаскивает 5–10 полезных фраз, пользователь отмечает нужные.
3. **Вручную.** en + ru + пример. Работает без ИИ.
4. **Читать.** Режим чтения, см. 9.3.

Элементы "из жизни" идут в Разведку первыми.

### 9.3 Режим чтения (четвёртый вход "Из жизни")

Как работает
- Пользователь вставляет любой английский текст (статья, субтитры, переписка, пост). Текст сохраняется в IndexedDB в личную библиотеку, к нему можно вернуться.
- Текст открывается в удобной читалке. Крупный шрифт, тёмная тема, без лишнего интерфейса.
- Тап по слову выделяет его. Протяжка пальцем или тап по второму слову расширяет выделение до фразы. Выделять можно от 1 до 8 слов подряд.
- Над выделением появляется панель с кнопками "Послушать" (TTS), "Перевод" и "В поход".
- "В поход" создаёт элемент `phrase`. Предложение, в котором стояла фраза, сохраняется как первый контекст с пометкой `source: 'life'`.
- С ИИ: перевод фразы в этом контексте, ещё 2 контекста, ситуации для Перевода и Экспромта, ложные смыслы для Свайпа. Один запрос на фразу, через общую очередь и кэш.
- Без ИИ: пользователь сам вводит перевод. Элемент создаётся с одним контекстом, недостающие поля досоздаются позже, когда ИИ станет доступен. До этого элемент ходит только по приёмам, которым хватает имеющихся данных (Пропуск, Перевод, Диктант, Голос).
- Уже добавленные фразы в тексте подсвечены. Цвет показывает статус (новая, в бою, немезида, приручена).
- Элементы из режима чтения идут в Разведку первыми, как и остальные "из жизни".

Библиотека
- Список сохранённых текстов с названием, датой и числом взятых фраз.
- Удаление текста не удаляет созданные из него элементы.

Данные
- Новая таблица `Text { id, title, body, createdAt }`.
- У `Item` необязательное поле `textId`.

Ограничения
- Никакой встроенной библиотеки чужих материалов и никакой загрузки по ссылке. Только то, что пользователь вставил сам.
- Длинный текст рендерить частями, чтобы читалка не тормозила на телефоне.

Самопроверка для этой функции
- Вставить текст, выделить одно слово и фразу из нескольких слов, добавить, убедиться что элемент появился в ближайшей Разведке с правильным контекстом.
- Проверить выделение на размере 393×873 с touch-эмуляцией, в том числе у края экрана и на переносе строки.
- Проверить подсветку статусов после боя и то, что удаление текста не ломает элементы.

## 10. ИИ-слой (только бесплатно)

Игра обязана полностью работать без ИИ и без сети. ИИ это усилитель.

### 10.1 Провайдеры

Интерфейс `AIProvider` с методом `complete(prompt, jsonSchema)`.
- **Gemini API, бесплатный тариф Google AI Studio** (основной). Ключ пользователь получает сам и вводит в настройках. Id модели хранится в настройках, по умолчанию актуальная бесплатная Flash-модель. При настройке сверить название модели и лимиты в AI Studio, они меняются.
- **Groq, бесплатный тариф** (запасной, OpenAI-совместимый API).

Ключи хранятся только в IndexedDB на устройстве. В репозиторий и в бандл не попадают. Это допустимо только потому, что приложение личное.

На бесплатном тарифе Google может использовать запросы для улучшения своих продуктов. В запросы не класть ничего личного, кроме учебных фраз и ответов в сценах.

### 10.2 Экономия квоты

- Не больше 100 запросов в день.
- Очередь, не чаще одного запроса в 5 секунд, на 429 пауза и повтор с растущим интервалом.
- Всё сгенерированное кэшируется в IndexedDB.
- Раз в день одним запросом досоздавать свежие контексты и ситуации для элементов, которые придут завтра.
- При исчерпании лимита или офлайне игра молча переключается на режим без ИИ.

### 10.3 Задачи и контракты (ответ строго JSON)

**checkProduction** (Своя фраза, Экспромт, Встреча)
```json
{
  "ok": true,
  "usedTarget": true,
  "corrected": "string",
  "errors": [
    { "wrong": "string", "right": "string", "ruleRu": "одно предложение", "patternId": "articles | null" }
  ],
  "moreNatural": "string | null"
}
```

**sceneTurn**. Вход: сцена, цель, история, целевые фразы. Выход: реплика персонажа (до 25 слов, B2), checkProduction для последнего ответа, а на последнем ходу `outcome: "success" | "partial" | "fail"` и одна фраза почему.

**freshContexts**. Вход: список элементов. Выход: по 2 новых предложения и 1 новой ситуации на элемент. Нужны, чтобы пользователь учил фразу, а не запоминал одно предложение.

**fromLife**. Вход: русская фраза или английский текст. Выход: массив элементов в формате seed.

**mnemonic**. Вход: элемент и история ошибок. Выход: короткая мнемоника на русском.

Системная установка для всех запросов: пользователь B2, объяснения на русском, одно предложение, без терминов, английский простой и разговорный.

## 11. Модель данных

```ts
type ItemType = 'phrase' | 'word' | 'pattern';

interface Item {
  id: string;
  type: ItemType;
  land: string;
  en: string;
  ru: string;
  accept: string[];
  contexts: { en: string; ru: string; source: 'seed' | 'ai' | 'life' }[];
  promptsRu: string[];       // ситуации для Перевода и Экспромта
  questionEn: string;        // вопрос для Своей фразы
  falseMeanings: string[];
  source: 'seed' | 'life' | 'ai-correction';
  createdAt: number;
  textId?: string;           // текст из режима чтения, откуда взята фраза
}

interface Text { id: string; title: string; body: string; createdAt: number; }   // библиотека режима чтения

interface Progress {
  itemId: string;
  stage: 0 | 1 | 2 | 3 | 4 | 5;
  fsrs: Card;                // из ts-fsrs
  lapses: number;
  failedRunsInRow: number;
  lastMove: MoveId | null;
  inDebt: boolean;
  debtStreak: number;        // 0..2
  nemesis: null | { since: number; winsOverHero: number; defeatedDays: string[]; mnemonic?: string };
  mastered: boolean;
}

interface Attempt {
  id: string; itemId: string; move: MoveId; ts: number; runId: string;
  correct: boolean; rating: 1 | 2 | 3 | 4; ms: number;
  hintUsed: boolean; risked: boolean; answer: string;
}

interface Run {
  id: string; seed: number; kind: 'run' | 'sortie';
  map: MapNode[][]; position: { step: number; node: number } | null;
  hp: number; maxHp: number; boons: BoonId[];
  runes: number; combo: number; failedItemIds: string[];
  status: 'active' | 'won' | 'retreated';
  startedAt: number;
}

interface PatternStat { patternId: string; last20: boolean[]; activeDays: string[]; active: boolean; }

interface Profile {
  xp: number; level: number; runes: number;
  streak: number; freezes: number; lastActiveDay: string;
  camp: Record<UpgradeId, number>;
  trophies: string[];
  unlockedLands: string[];
  settings: Settings;
}
```

Тестами Vitest покрыть: долги и смену приёма, ступени и Рискнуть, появление и победу над немезидой, регулятор нагрузки, маппинг оценок, проверку ответов, генерацию карты по правилам, сборку Эхо, то что усиления не влияют на оценку FSRS.

## 12. Визуальный стиль и UX

- Интерфейс на русском. Короткие подписи, без канцелярита.

## 16. Самопроверка (обязательно после каждого этапа)

Этап не считается готовым, пока Claude Code сам не запустил приложение и не прошёл его руками как пользователь. Успешная сборка и зелёные тесты не являются доказательством, что всё работает и нормально выглядит.

Порядок

1. **Автопроверки.** `tsc --noEmit`, линтер, Vitest, production-сборка. Всё без ошибок.

2. **Запуск и ручной проход в браузере.** Поднять dev-сервер и управлять реальным браузером. Если подключены браузерные MCP-инструменты (Playwright MCP, Chrome DevTools MCP), использовать их. Если нет, поставить Playwright с Chromium и писать сценарии в `e2e/`.
   - Основной размер окна 393×873 с мобильной эмуляцией и touch. Дополнительно 360×800 и 1280×800.
   - Пройти настоящий сценарий кликами и вводом, а не открыть одну страницу. Минимум: старт похода, верный ответ, намеренно неверный ответ, возврат должника другим приёмом, Рискнуть, выбор усиления, доход до Эхо, экран итога, отступление при здоровье 0.
   - Через dev-панель сдвинуть время и проверить следующий день: должники в Засаде, повторения по FSRS, появление немезиды после трёх провалов и её уничтожение после побед в три дня.
   - Перезагрузить страницу посреди похода и убедиться, что он продолжается с того же места.
   - Включить офлайн и убедиться, что приложение открывается и поход проходится.

3. **Глаза.** На каждом экране и в каждом важном состоянии сделать скриншот, открыть его и посмотреть самому. Искать: вылезший или обрезанный текст, наложение элементов, слишком мелкие кнопки, нечитаемый контраст, поле ввода или кнопку под клавиатурой, горизонтальную прокрутку, пустые состояния без объяснения, дёрганые анимации. Отдельно оценить по-честному: выглядит ли это как игра, в которую хочется играть, или как форма с кнопками. Если второе, доработать до отчёта.

4. **Консоль и сеть.** В консоли браузера не должно быть ошибок и предупреждений React. Не должно быть упавших запросов.

5. **Исправить и повторить.** Всё найденное исправить и пройти сценарий заново. Сценарии из `e2e/` сохранять и гонять на каждом следующем этапе как регресс.

6. **Отчёт.** Записать `docs/verification/stage-N.md`: что проверено, какие сценарии пройдены, пути к скриншотам, что было найдено и исправлено, что осталось известной проблемой.

7. **Что нельзя проверить без человека.** В конце отчёта дать пользователю короткий чек-лист для проверки на реальном телефоне: установка PWA, микрофон и распознавание речи, голоса озвучки, вибрация, поведение экранной клавиатуры, плавность анимаций. Не писать, что эти вещи работают, если они не проверены.

8. **Пуш.** Только после пройденной самопроверки закоммитить и запушить этап по правилам раздела 19.

Запрещено сообщать "готово" по одному только факту, что код написан и собирается.

## 17. Этапы

Каждый этап заканчивается рабочим приложением, самопроверкой по разделу 16, пушем по разделу 19 и остановкой.

**Этап 0. Каркас.** Git и подключение репозитория (раздел 19), Vite, TS, Tailwind, Dexie, Zustand, PWA, роутинг, пустые экраны, dev-панель, Playwright, CLAUDE.md.
Готово, когда приложение открывается офлайн, первый e2e-сценарий проходит и первый пуш лежит в репозитории.

**Этап 1. Один бой. Прототип веселья.** `engine/` с тестами, 100 элементов seed и 2 pattern, приёмы Свайп, Сборка, Пропуск, Перевод, экран боя со шкалой замаха, здоровьем, комбо, должниками и процедурными врагами. Без карты. Кнопка "В бой" запускает один бой из очереди.
Готово, когда ошибка гарантированно возвращает врага другим приёмом, а бой ощущается как бой.
**После этого этапа обязательная пауза. Пользователь играет несколько дней и даёт правки по балансу и ощущениям. Дальше не идти без его слова.**

**Этап 2. Поход.** Карта, типы узлов, Разведка со Знакомством, Привал с Ловушкой, усиления, Эхо, отступление, итог, Вылазка, остальной seed. Режим чтения без ИИ (9.3): читалка, выделение слов и фраз, ручное добавление с переводом, библиотека текстов. Добавлено в план после того, как этап 2 был сдан, поэтому делается отдельным шагом **2а** сразу после этапа 4, с той же самопроверкой и тегом `stage-2a`.

**Этап 3. Звук и речь.** TTS, На слух, Диктант, Голос с запасным режимом, Экспромт, звуки и вибрация.

**Этап 4. Немезиды и развитие.** Логово, Зал трофеев, руны, Лагерь с улучшениями, уровень, Земли, Летопись, серия с заморозками, все празднования.

**Этап 5. ИИ.** Провайдеры, очередь, кэш, checkProduction, Своя фраза, Встречи, материализация ошибок, "Из жизни", обогащение фраз из режима чтения (перевод в контексте, контексты, ситуации, ложные смыслы, досоздание недостающих полей у элементов, добавленных без ИИ), свежие контексты, мнемоники.

**Этап 6. Полировка.** Статистика и недельный отчёт, экспорт и импорт, управление с клавиатуры, оптимизация бандла и анимаций, деплой.

## 18. Чего не делать

- Не добавлять аккаунты, бэкенд, синхронизацию через сервер.
- Не добавлять механики, которые дают победу без ответа на английском.
- Не давать игровым эффектам менять оценку FSRS.
- Не писать длинные грамматические объяснения.
- Не блокировать игру за ошибки и пропуски дней.
- Не тянуть тяжёлые библиотеки ради одного эффекта.
- Не объявлять этап готовым без самопроверки из раздела 16.
- Не коммитить ключи и не делать force push (раздел 19).

## 19. Git и репозиторий

Весь код живёт в `https://github.com/nasraddinzade/learning-game.git`.

Подключение (этап 0)
- `git init`, ветка `main`, `git remote add origin https://github.com/nasraddinzade/learning-game.git`.
- Перед первым пушем проверить, что лежит в удалённом репозитории (`git ls-remote`, `git fetch`). Если там уже есть коммиты, ничего не перезаписывать. Подтянуть их, показать пользователю и спросить, как поступить.
- Авторизация берётся из локальных настроек git пользователя. Если пуш не проходит из-за доступа, остановиться и сказать об этом. Не просить токен в чат и не записывать его в файлы.

Правила
- Коммитить небольшими осмысленными шагами по ходу работы. Сообщения на английском в стиле conventional commits (`feat:`, `fix:`, `test:`, `chore:`, `docs:`).
- Пушить в `main` после каждого этапа и только после пройденной самопроверки. В конце этапа ставить тег `stage-N`.
- В отчёте этапа указывать хеш последнего коммита и подтверждение, что пуш прошёл (`git status` чистый, локальная ветка совпадает с `origin/main`).
- Никогда не делать `push --force`, не переписывать историю, не менять глобальные настройки git.
- `.gitignore` с первого коммита: `node_modules`, `dist`, `.env*`, `playwright-report`, `test-results`, служебные файлы редактора.
- Ключи ИИ не попадают в репозиторий ни в каком виде. Они вводятся в настройках приложения и хранятся только на устройстве. Перед каждым пушем проверять diff на случайные секреты.
- `SPEC.md`, `CLAUDE.md` и отчёты из `docs/verification/` коммитить. Скриншоты в отчётах сжимать и держать только ключевые, чтобы репозиторий не раздувался.
